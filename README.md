# 自用 GKD 开屏订阅

仅维护应用启动时带“跳过”按钮的全屏广告规则。按需适配，不追求覆盖所有应用。

## 添加订阅

[订阅文件](https://raw.githubusercontent.com/henjicc/gkd-personal/main/dist/gkd.json5)

将链接复制到 GKD → 订阅 → 添加订阅。之后下拉刷新可检测更新。

## 当前适配

| 应用     | 状态                        | 说明                                                                             |
| -------- | --------------------------- | -------------------------------------------------------------------------------- |
| 哔哩哔哩 | 2026-11-07 本机反馈验证成功 | 匹配 `count_down` / `skip`，使用 `clickCenter` 模拟点击按钮中心；验证版本 9.18.0 |

不处理首页轮播、信息流、青少年弹窗或自动更新提示。更多应用按实际需求加入。

## 与其他订阅共存

同一应用的开屏规则只启用一份。使用本订阅处理哔哩哔哩时，关闭其他订阅和本地订阅里对应的开屏规则。其他应用的原规则可以继续使用。

## 开发与发布

使用 Node.js 24、pnpm 11.9.0：

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm build
```

规则位于 `src/apps/`，订阅信息位于 `src/subscription.ts`。提交到 `main` 后，GitHub Actions 自动检查并构建，把结果写回 `dist/`。只有成功生成的订阅会发布；手机下拉刷新后取得更新。

订阅 ID 固定，不沿用其他订阅或 GKD 内部的负数 ID。构建工具根据规则变更更新版本。`dist/` 是生成文件，修改规则请编辑 `src/`。

## 维护原则

- 只增加开屏跳过规则，保留明确的按钮识别条件。
- 每个应用单独决定点击方式，不把所有按钮一律改成坐标点击。
- 规则校验通过与广告实测成功分别记录；无法复现广告时标记为待验证。
- 参考上游时逐项比较、测试后合入，不自动覆盖本机修复。
- 不提交手机截图、完整诊断日志、安装应用清单、凭据或真实用户数据。

模板及规则来源见 [SOURCES.md](SOURCES.md)。本仓库不提供覆盖所有广告样式的保证。
