# 自用 GKD 开屏订阅

从现用订阅完整提取开屏广告规则，以此为基线边用边测、逐项修改。

## 订阅链接

**[订阅链接（main）](https://raw.githubusercontent.com/henjicc/gkd-personal/main/dist/gkd.json5)**

必须使用指向 `main` 的链接。GKD 1.13.0 检测更新时使用添加订阅时保存的链接，并以它为基准解析 `checkUpdateUrl`，不会改用文件内的 `updateUrl`。固定到某个提交的链接永远停在该版本，下拉刷新只会提示“暂无更新”。已用旧固定链接添加的，在 GKD 订阅页编辑该订阅，把链接改为上面的地址即可，订阅 ID 和规则开关不变。刚推送后 raw 地址可能有几分钟缓存。

GKD → 订阅 → 添加订阅，粘贴链接。之后在订阅页下拉刷新即可检测更新。订阅 ID 为 `1874130597`，独立于原订阅 `667`。

本订阅与原订阅有大量重复规则。切换后建议停用原订阅，并关闭本地订阅中的哔哩哔哩“开屏广告-触屏点击测试”，避免同一广告被多份规则同时处理。原订阅可以保留用于回退。

## 后续如何修改

1. 确认目标应用包名，编辑 `src/apps/<包名>.ts`。全局开屏规则在 `src/globalGroups.ts`，分类在 `src/categories.ts`。
2. 广告出现后，结合 GKD 触发记录和诊断判断：没有匹配到就核对按钮节点、选择器及匹配时机；已触发但没有关闭，再验证点击方式。
3. 尽量在原规则上做最小修改。若需要触屏点击，只给对应子规则添加 `action: 'clickCenter'`，不添加盲点固定坐标的通用规则。
4. 保留订阅 ID、应用 ID、规则组 key 和已有规则 key。新规则使用不重复的 key，防止触发记录和启用状态错位。
5. 在本页“当前本地修改”表追加修改原因、验证日期和结果；无法复现广告时写“待验证”，不能用静态检查通过代替广告实测成功。
6. 运行检查并提交到本仓库 `main`。GitHub Actions 自动生成新版本订阅，完成后手机下拉刷新。

本地开发使用 Node.js 24、pnpm 11.9.0：

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm build
```

`dist/` 是生成结果，不直接手改。构建工具在规则实际变化时递增订阅版本；重复构建没有变化则不递增。也可以只提交校验通过的 `src/` 改动，由 GitHub Actions 构建并提交 `dist/`。

参考：[规则字段](https://gkd.li/api/)、[点击方式说明](https://gkd.li/api/interfaces/RawRuleProps#action)、[订阅更新机制](https://gkd.li/api/interfaces/RawSubscription)。

## 上游更新与隐私

本仓库采用固定基线，**不会自动把上游新版本覆盖进来**。需要参考上游修复时，对比相应应用的开屏组，在保留本地修改的基础上合入并验证；不重新导入无关类别。

不提交手机截图、完整诊断日志、安装应用清单、凭据或真实用户数据。这里的应用列表来自公开上游规则，不是个人手机应用清单。来源和补充记录见 [SOURCES.md](SOURCES.md)。
